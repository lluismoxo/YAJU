Earlier in the generation

  • Oran 3.1 opened the third generation with the question nobody could answer before: what does each agent actually cost? Spend is attributed per agent and broken down by user and by model, and reported in dollars rather than tokens. At this stage it was reporting only, with no limits attached to it yet.

    Cost attributed per agentReported in dollars

  • Oran 3.2 turned that visibility into control. Circuit-breaker budgets set hard limits per workspace and team, warn as the limit approaches, block automatically when it is reached, and forecast the rest of the cycle. An overrun is stopped while it happens instead of being explained afterwards.

    Budgets per workspaceAutomatic block at the limit

  • Two generations came before Oran. Keter was the first runtime, able to execute a single agent and little else, and grew across eight versions into a catalogue with a named owner per agent and a central credential store. Nahar followed across four more. Every version is listed on the models overview.

    Keter and Nahar

Oran began with the question nobody could answer before: what does each agent actually cost? Six versions later it attributes spend per agent, stops an overrun before the invoice, scores every run against your own criteria, lowers cost without losing quality, and lets teams share agents instead of rebuilding them.

Under the hood

What changed with Oran

Cost you can attribute

Spend is attributed per agent and broken down by user and model, reported in dollars rather than tokens. The question of what an agent costs finally has an answer, and it arrives before the invoice does.

Budgets that stop an overrun

Circuit-breaker budgets per workspace and team warn as the limit approaches and block when it is reached, with a forecast for the rest of the cycle. Control happens at the moment of spend, not in the monthly review.

Quality enforced on every run

Evals check every run against behavioural, structural, latency and cost criteria, and halt an agent when one fails. Optimizer then lowers spend measured against those same evals, so cheaper never quietly means worse.
